## Human editor workflow

Use `show` when a human wants to edit the whole file, then `hide` immediately afterward. Agents and automation should use the targeted locked-file commands below instead.
```bash
# Unlock (config.vars → config.unlocked.vars)
vars show

# Edit config.unlocked.vars in your editor

# Lock (config.unlocked.vars → config.vars)
vars hide
```

### show

```bash
vars show [file]
```

Decrypts a `config.vars` file and renames it to `config.unlocked.vars`. The encrypted values are replaced with their plaintext. Edit the file directly, then run `hide`.

Before decrypting, vars checks for common problems:

- Warns if `.varskey` is missing
- Warns if the pre-commit hook isn't installed

**Flags**

| Flag | Short | Description |
|------|-------|-------------|
| `--file <path>` | `-f` | Target a specific `.vars` file |

```bash
vars show -f staging.vars
```

### hide

```bash
vars hide
```

Encrypts ALL unlocked `.unlocked.vars` files. Scans for any `*.unlocked.vars` file in the current project and encrypts each one, renaming it back to `.vars`. You don't need to specify a file.

Encryption is all-or-nothing per file. If any value fails, that file stays untouched.

If schemas changed since the last `gen` run, `hide` regenerates the TypeScript types automatically.

**Flags**

| Flag | Short | Description |
|------|-------|-------------|
| `--file <path>` | `-f` | Target a specific file only |

```bash
vars hide -f staging.vars
```

## Locked-file edits

`add`, `set`, `remove`, and `apply` modify `config.vars` directly. Secret inputs are encrypted before the file is atomically replaced; these commands never create `config.unlocked.vars`.

Qualified names keep public and secret values together by integration:

```bash
vars add stripe.PUBLISHABLE_KEY --public --value "pk_test_..."
vars add stripe.SECRET_KEY --value-file /run/secrets/stripe-key \
  --pin-file /run/secrets/vars-pin
```

This creates or updates a group containing both repository-readable and encrypted values.

<Accordions type="single">
<Accordion title="add — add a variable">

```bash
vars add NAME
vars add integration.NAME
```

Names must be `UPPER_SNAKE_CASE`. `--public` keeps the value plaintext; without it, values written to a locked file are encrypted.

**Flags**

| Flag | Description |
|------|-------------|
| `--public` | Keep the value repository-readable |
| `--schema <zod>` | Set the Zod schema |
| `--value <value>` | Set a value directly |
| `--value-file <path>` | Read a value from a file |
| `--dev`, `--staging`, `--prod` | Set environment values |
| `--dev-file`, `--staging-file`, `--prod-file` | Read environment values from files |
| `--pin-file <path>` | Read the PIN without exposing it in process arguments |
| `--key-file <path>` | Use an externally provisioned encrypted key envelope |

</Accordion>
<Accordion title="remove — delete a variable">

```bash
vars remove NAME
vars remove integration.NAME
```

Deletes the variable, its environment values, and metadata directly from the locked file. Removing ciphertext does not require a PIN.

</Accordion>
<Accordion title="set — update a value">

```bash
vars set NAME --value "new-value"
vars set integration.SECRET --value-file /run/secrets/new-value \
  --pin-file /run/secrets/vars-pin
```

Updates a variable without unlocking the file. Environment flags and their `-file` variants update individual environment values.

</Accordion>
<Accordion title="apply — atomically upsert an integration">

`apply` reads variable and group declarations from stdin. Omitted variables remain unchanged:

```bash
vars apply --pin-file /run/secrets/vars-pin <<'VARS'
group stripe {
  public PUBLISHABLE_KEY = "pk_test_..."
  SECRET_KEY = "sk_test_..."
}
VARS
```

The plaintext fragment exists only in the command input. Secret declarations are encrypted before `config.vars` is replaced.

</Accordion>
<Accordion title="ls — list variables">

```bash
vars ls
```

Without a file argument: lists all `*.vars` files in the project with their lock state and variable count.

```text
FILE              STATE     VARS
config.vars       locked    12
staging.vars      unlocked   5
```

With a file argument: shows each variable's schema, which envs have values, required/optional status, and metadata (description, owner, expiry, deprecation). Deprecated vars show with strikethrough.

```bash
vars ls config.vars
```

```text
NAME             SCHEMA                  ENVS                  STATUS
DATABASE_URL     z.string().url()        dev, staging, prod    required
PORT             z.coerce.number()       default               optional
~~OLD_API_URL~~  z.string().url()        default               deprecated
```

**Flags**

| Flag | Short | Description |
|------|-------|-------------|
| `--file <path>` | `-f` | Use a different vars file |

</Accordion>
</Accordions>
